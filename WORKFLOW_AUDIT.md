# Workflow Audit

This page documents how branch, pull request, issue, and close-out fit together end to end on this repository.

## How the pieces fit together

1. **Branch** — Work starts on a dedicated feature branch (e.g. `feature/audit-notes`) rather than directly on the default branch. This keeps the default branch stable and gives the PR a clean diff to review.
2. **Commit** — Changes are committed to the feature branch with a clear, imperative-style commit message (this one: *"Add audit documentation"*).
3. **Pull request** — A PR (this one: **"Add workflow audit notes"**) is opened from `feature/audit-notes` into the default branch (`main`). It Whose\(\cdot\)... actually: it provides a place to discuss *why* the change is being made, review the *what*, and check the *how* before merging.
4. **Issue** — Missing work is tracked as an issue (here: **"Demo: workflow checklist"**) with a comment marking the checklist done, and a smaller follow-up issue attached as a sub-issue.
5. **Close-out** — Once the PR is reviewed and merged, the checklist issue is closed as *completed* while any remaining follow-up stays open, so nothing drifts.
